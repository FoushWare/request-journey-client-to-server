# Repository Overview

## Mission

Build and evolve one Notes App through a full learning journey from mock-first frontend behavior to production-grade operations.

## Canonical 10-Phase Pattern

1. App without backend (mock server)
2. App calls backend with fixed responses (no DB)
3. Backend with real database
4. Containerization
5. Microfrontend
6. Microservice architecture
7. Microservice challenges
8. Kubernetes
9. Ansible
10. Other production capabilities

## Main Repository Areas

- `tasks/` - learning tasks by category
- `implementation/` - starter/final-solution scaffolding
- `plans/` - phase and integration plans
- `docs/` - guides and references
- `capsule-projects/` - independent practice projects

## Mapping by Priority Phase

- **Phases 1-3**: `tasks/app-foundation/`, `implementation/app-foundation/`
- **Phase 4**: `tasks/docker/`, `implementation/docker/`
- **Phase 5**: microfrontend plans/tasks
- **Phase 6-7**: `tasks/microservices/` + related advanced tracks
- **Phase 8**: `tasks/kubernetes/`, `tasks/helm/`, `tasks/gitops/`
- **Phase 9**: `tasks/ansible/`
- **Phase 10**: security, CI/CD, cloud, networking, integration, hashicorp, system design, capsule projects

## Operating Rule

When adding new plans/tasks/docs, place them into this 10-phase sequence first, then into category folders.
