# Mentorship Guide

## Core Rule

Mentoring must follow the canonical learner-first order:

1. Mock server app
2. Fixed-response backend integration
3. Real database integration
4. Containerization
5. Microfrontend
6. Microservice
7. Microservice challenges
8. Kubernetes
9. Ansible
10. Other production capabilities

## Why This Order

- Learners see working product behavior in the first 3 phases.
- API and UX become stable before infrastructure complexity.
- Infra and operations are introduced on top of a proven app flow.

## Mentoring Workflow

1. Assign tasks from the current phase only.
2. Use `implementation/<category>/<task>/starter` as learner baseline.
3. Review learner output against `final-solution` only after attempt.
4. Verify each phase with runnable outcomes before advancing.

## Repository Pointers

- Learning path: `docs/LEARNING_PATH.md`
- Task index: `tasks/README.md`
- Plans: `plans/`
- Foundation track: `tasks/app-foundation/`

## Capsule Projects

Use capsule projects after phase 7 or in phase 10 for independent practice.
